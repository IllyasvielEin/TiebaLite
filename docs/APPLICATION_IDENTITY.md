# Learning edition application identity

The owner-approved application ID is `io.github.illyasvielein.tiebalite`, with
launcher label `贴吧 Lite`. It is a separate Android installation identity
from upstream `com.huanchengfly.tieba.post`. It does not inherit upstream's app
data or signing identity and cannot update an upstream installation in place.

The Kotlin/Java namespace remains `com.huanchengfly.tieba.post`; class names,
launcher aliases and custom view names are not package-installation identifiers.
Four static shortcuts and the vendor EasyGo client identifier target the new app.
FileProvider and AndroidX startup authorities derive from applicationId, and
file sharing derives its authority from context.packageName. Credential backup
exclusions include the new full `:oksign` WebView process directory.

No stable signing key is generated by this change. The default release proof
remains unsigned; optional signing requires the owner's separately configured
key. The About screen source button links to this fork so users can find the modified
source. Original authorship, upstream license and source notices remain intact.

The approved support range is Android 15 and later (minSdk 35), with compile/target
API 37. No maximum OS version is imposed. Source checks are not proof of the
merged manifest or installed behavior: CI must build and inspect the APK, and
runtime checks must cover launcher aliases, shortcuts, URI/FileProvider sharing,
and separate installation on Android 17.

CI uses the preinstalled official Build Tools `aapt2 dump badging` output to fail
closed on a wrong package, min/target SDK, label, maximum SDK, or removed sensitive
permissions. The text evidence is archived with validation reports. See
https://developer.android.com/tools/aapt2 . This is APK-manifest evidence, not
installed-device behavior or a complete security validation.
